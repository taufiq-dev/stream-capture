Rule 1 · Camera

Select the camera by its capabilities. Do not select a camera by its position in the enumerateDevices() list.

Rule 2 · Resolution

Cut the crop from the source frame in source pixels. Do not cut the crop from a canvas that has the size of the screen.

1General

1.1Purpose

The stream-capture component is a full-screen camera sheet for React. It takes a photo of an identity card in a mobile browser. It gives the photo to the host application as a JPEG data URL.

A simple camera sheet has two problems on modern phones. This component solves the two problems.

1.2Problem 1: the incorrect camera

The constraint facingMode: "environment" gives a rear camera. It does not always give the main rear camera. On a phone with many lenses, the browser can open the telephoto lens or the macro lens. Then the preview is dark and narrow, and it is difficult to focus the lens on a card.

1.3Problem 2: low resolution

A simple sheet draws the preview on a canvas that has the size of the screen. As a result, a guide box that is 358 CSS px wide gives a crop that is 358 px wide. This resolution is not sufficient for optical character recognition (OCR).

This component cuts the crop from the preview frame at full resolution. The crop is then approximately 1000 to 2000 px wide.

3Sequence of operation

This is the normal sequence for one session. Each paragraph that follows gives the details of one step.

  1. The host application shows the sheet. The sheet moves up from the bottom of the screen in 600 ms.
  2. The sheet locks the scroll position of the page.
  3. The hook selects and opens the main rear camera.
  4. The preview starts. The sheet shows the video only after the first frame plays.
  5. The user puts the card in the guide box and pushes the shutter button.
  6. The component takes the photo. It shows the photo on the same area of the screen.
  7. The sheet moves down in 600 ms.
  8. The sheet calls uploadImage(dataUrl, meta) and then setStream(false).

If the user pushes Cancel, the sheet moves down and calls setStream(false). It does not call uploadImage.

4Camera selection

4.1Description

The browser does not give the camera list in a stable sequence. As a result, the position of a camera in the list has no meaning. The component reads the capabilities of each camera and gives each camera a score.

4.2Steps of the selection

The function selectMainRearCamera() does these steps:

  1. The component opens the default rear camera with facingMode: "environment". This step gets the camera permission. It has no time limit, because the user can wait at the permission prompt.
  2. The component gets the list of video inputs with enumerateDevices(). The labels and the capabilities are available only after permission.
  3. The component reads the stored camera from localStorage. If the device ID and the label agree with a camera in the list, it uses that camera. Go to step 7
  4. If there is only one camera, the component uses the default stream. Stop here
  5. The component reads the capabilities of each camera. It uses the sources that do not open a camera first. Refer to table 4-1.
  6. The component gives a score to each camera. It removes the cameras that are not rear cameras. It selects the camera with the highest score.
  7. If the default stream is already the selected camera, the component keeps it. If not, it opens the selected camera. It stores the selection in localStorage.

4.4Rear camera test

If the capabilities give a facingMode value, the component uses that value. If not, it uses the label. A label with back, rear or environment identifies a rear camera.

A label with front, user or selfie identifies a front camera. The component identifies a camera with an empty label as a rear camera. This prevents an empty camera list on browsers that do not show labels.

4.5Stored camera

The component stores the device ID and the label in localStorage, with the key camera-selection/v1. On the next visit, this removes the probe step.

The component still reads and scores the camera list. This step is fast, and it opens no camera. As a result, the user can switch back to a better camera.

Chromium keeps a device ID until the user clears the site data. Safari changes the device IDs between sessions. On Safari, the stored camera does not agree, and the full selection occurs.

If a stored device ID is stale, getUserMedia gives OverconstrainedError or NotFoundError. The component then removes the stored camera and opens facingMode: "environment".

CAUTION

Validate all data from localStorage before you use it. Other scripts and earlier versions can write incorrect data. The component validates the stored camera with valibot.

4.6Manual switch

Set enableCameraSwitch to show the switch button. The button shows only when there are two or more rear cameras. Each push opens the next rear camera in the score sequence. The component stores the manual selection.

5Preview

The component requests a preview of 3840 × 2160 px as ideal values. An ideal value is not a hard limit. A phone with a 1080p maximum gives 1080p, and the crop is then smaller.

The stream can be open before the video plays. During this interval, the video element shows its poster. The Android WebView poster is a grey play symbol.

To prevent this, the component sets a transparent GIF of 1 × 1 px as the poster. It shows the video only after the playing event.

Some WebView host applications do not allow media playback without a user gesture. If video.play() gives NotAllowedError, the component shows an error message.

iOS stops the camera track when the application goes into the background. The component then shows an error. Without this error, the user cannot see the difference between a stopped frame and a live preview.

6Capture

6.1Sharpest frame

When the user pushes the shutter button, the component examines 4 frames at intervals of 120 ms. For each frame, it calculates the variance of a Laplacian on a small grey copy.

The grey copy is 320 px wide. A high variance shows a sharp frame. The component compares the frames with each other only. It does not use the variance as an absolute limit.

The component draws a frame at full resolution only if that frame is the sharpest frame so far. It uses one canvas for this.

A 4K canvas uses approximately 30 to 50 MB of memory. With one canvas, the memory stays in the canvas memory limit of mobile Safari.

6.2From the guide box to source pixels

The guide box is a DOM element. At capture, the component reads the rectangles of the guide box and the video element with getBoundingClientRect(). As a result, the crop is always the area that the user saw.

The video element uses object-fit: cover. The browser scales the frame to fill the element, and the overflow is not visible. The component calculates the scale and the overflow, and then converts CSS px to source px.

scale    = max(element width ÷ source width, element height ÷ source height)
overflow = (source width × scale − element width) ÷ 2
source x = (box x + overflow) ÷ scale
source w = box width ÷ scale

Then the component adds a margin of 8% of the box on each side. The backend uses this margin for its own edge detection and perspective correction. The component clamps the crop to the edges of the frame.

The crop is a 1:1 copy of the source pixels. The component does not resample the crop.

6.3Encoding under the size limit

The upload limit is 5 MB. The function encodeUnderBudget() does these steps:

  1. If the long edge is more than 3200 px, the component scales the image down to 3200 px.
  2. The component encodes the JPEG at quality 0.95. If the file is larger than 5 MB, it encodes again at 0.92, 0.90, 0.88 and 0.85.
  3. The component does not go below quality 0.85. It decreases the width and the height by 15%. Go to step 2
  4. After 6 attempts, the component stops with an error.

The component removes pixels before it decreases the quality. JPEG block artifacts cause more problems for document recognition than a small decrease in resolution.

6.4After the capture

The component pauses the video. It puts the captured image on the screen at the exact position of the crop. The user can then see that the photo agrees with the guide box.

Then the sheet moves down. After 600 ms, the sheet calls uploadImage(dataUrl, meta).

CAUTION

Do not crop the first JPEG to make the second file. The component must cut the second file from the full-resolution frame. A crop of a JPEG keeps the block artifacts of the first encode.

8Sheet geometry

On mobile Safari, the units vh and dvh do not always agree with the visible screen. Because of this, the component measures the sheet and writes --sc-viewport-width and --sc-viewport-height.

On iOS, the layout viewport and the visual viewport can move apart after the permission prompt. A fixed sheet then stays above the screen. The component sets the position and the size of the sheet from window.visualViewport.

The component measures again after each resize, scroll and orientation change. After a status change, it measures again on the next frame and after 350 ms. iOS gives the final viewport size late.

The sheet also locks the page body at its scroll position. On iOS, a fixed overlay above a scrolled page moves by the offset of the visual viewport. When the sheet closes, the component returns the page to its scroll position.

The guide box size comes from one ratio, --sc-guide-ratio:

width  = min(viewport width − 32 px, 0.5 × viewport height × ratio)
height = width ÷ ratio
top    = (viewport height − height) × 0.2

9Events

The sheet sends all events through one function, emitEvent. Each event has a sessionId and an elapsedMs value. The sessionId changes each time the sheet opens.

The elapsedMs value is the time since the sheet opened. On camera_ready, this value is the time to the first preview.

Each session ends with one closed event or one abandoned event. It never sends the two. As a result, the funnel numbers agree.

The component catches all errors from the event handler. An error in analytics code cannot stop a capture.

CAUTION

Do not send camera.label to a third party without a privacy review. The label can help to identify the device.

11Rules for changes

Obey these cautions when you change the component.

CAUTION

Do not select a camera by its index in the enumerateDevices() list. The sequence is not stable, and the result can be a telephoto lens.

CAUTION

Do not cut the crop from a canvas with the size of the screen. The resolution then becomes too low for OCR.

CAUTION

Do not use takePhoto() with a guide box crop. On Android, it changes the field of view, and the photo does not agree with the preview.

CAUTION

Do not use vh or dvh for the sheet geometry. Use the measured --sc-viewport-* values.

CAUTION

Do not write element IDs or test IDs as fixed text. Make them from idPrefix. Host applications use these names for automation.

CAUTION

Keep SLIDE_MS (600) equal to the slide duration in stream-capture.styles.tsx. If the two values are different, the upload starts before or after the slide ends.

CAUTION

Do not add a second terminal event. Each session must end with one closed event or one abandoned event.

CAUTION

Do not add <StrictMode> to the test application. The double mount opens the camera two times.

11.1Procedure to examine a change

  1. Go to the stream-capture-demo/ folder.
  2. Run pnpm typecheck. This is the only automatic check. The repository has no tests and no linter.
  3. Run pnpm dev. Open the HTTPS address on a phone in the same network.
  4. Take a photo with the real phone camera. A desktop browser cannot test the camera selection.
  5. Record which steps you did on a phone and which steps you did not do.
NOTE

getUserMedia operates only in a secure context. http://localhost is a secure context. A LAN IP address without HTTPS is not a secure context.

NOTE

The test application does not send or store the photo. The photo stays in the memory of the page until you close the tab. The page tells the user this, because it requests camera permission on a public URL.
