Integration note · iOS host apps

The ID camera opens in a full-screen video player

In some iPhone apps, the camera opens in the native iOS video player. The customer must tap the × button to see the guide frame. The cause is one WebView setting in the host app. The web page cannot change this setting.

SymptomA video player covers the cameraOnly on iPhone. Android, and iOS apps that have the setting, show the guide frame at once.
CauseInline media playback is offThe app's WKWebView does not allow inline video. On iPhone, this is the default.
FixOne line in the native appSet allowsInlineMediaPlayback = true on the configuration, before you create the web view.
01 · What the customer sees

The same web page, two different host apps

02 · Why it happens

The app setting decides, not the web page

Stream Capture shows the camera in an HTML <video> element. It asks for inline playback with the playsinline attribute. In an app, iOS obeys this attribute only when the app's WKWebView allows inline media playback. If the app does not allow it, iOS plays every video in its full-screen player.

Where the page runsInline playbackResult
iPhone app, WKWebView with the default configurationfalse (iPhone default)Full-screen player
iPhone app, WKWebView with the fixtrueInline, as designed
iPad app, WKWebViewtrue (iPad default)Inline. A test on iPad does not show the problem.
Safari on iPhoneObeys playsinlineInline
Android app, Android WebViewNo such settingInline
03 · The fix

Allow inline media playback in the app's web view

Make this change where your app creates the web view that opens the ID capture page. Use the example for your framework. The second setting lets the muted preview start without a tap. It is recommended, but the first setting is the fix.

SwiftUIKit or SwiftUI (in makeUIView)
let config = WKWebViewConfiguration()
config.allowsInlineMediaPlayback = true
config.mediaTypesRequiringUserActionForPlayback = []
let webView = WKWebView(frame: .zero, configuration: config)
Objective-C
WKWebViewConfiguration *config = [[WKWebViewConfiguration alloc] init];
config.allowsInlineMediaPlayback = YES;
config.mediaTypesRequiringUserActionForPlayback = WKAudiovisualMediaTypeNone;
WKWebView *webView = [[WKWebView alloc] initWithFrame:CGRectZero configuration:config];
React Nativereact-native-webview, also Expo
<WebView
  source={{ uri }}
  allowsInlineMediaPlayback
  mediaPlaybackRequiresUserAction={false}
/>
Flutterwebview_flutter
import 'package:webview_flutter_wkwebview/webview_flutter_wkwebview.dart';

final params = WebKitWebViewControllerCreationParams(
  allowsInlineMediaPlayback: true,
  mediaTypesRequiringUserAction: const <PlaybackMediaTypes>{},
);
final controller = WebViewController.fromPlatformCreationParams(params);
Flutterflutter_inappwebview
InAppWebView(
  initialSettings: InAppWebViewSettings(
    allowsInlineMediaPlayback: true,
    mediaPlaybackRequiresUserGesture: false,
  ),
)
Cordovaconfig.xml
<preference name="AllowInlineMediaPlayback" value="true" />
CAUTION

Set the option on the configuration before you create the WKWebView. The webView.configuration property gives a copy. A change to that copy does nothing, and iOS shows no error.

// Does not work: the web view already exists.
let webView = WKWebView()
webView.configuration.allowsInlineMediaPlayback = true

If your app makes its web views in a shared factory, a container for mini-apps, or a third-party SDK, make the change there. If the team says "we already set this", examine this point first.

04 · How to confirm the fix

Test on an iPhone, not an iPad

  1. Install the app build with the change on an iPhone. An iPad allows inline playback by default, so it does not show the problem.
  2. Open the ID photo step in the app and allow camera access.
  3. Pass: the live camera picture shows inside the page, with the guide frame and the shutter button. No black player and no × button show first.
  4. Optional, with Safari Web Inspector: in debug builds, set webView.isInspectable = true (iOS 16.4 and later). Connect the iPhone to a Mac and open the page in Safari's Develop menu. In the console, type document.querySelector("video.camera").webkitDisplayingFullscreen. The result must be false. The result true means that the full-screen player is open.
05 · Why the web page cannot fix it

The page already asks for inline playback

The preview element in Stream Capture has the three attributes that inline playback needs:

<video autoPlay playsInline muted />
  • iOS ignores playsinlineWhen the app does not allow inline playback, iOS ignores this attribute. No other HTML or JavaScript option changes this.
  • Code cannot close the playerIf the page closes the full-screen player with code, iOS pauses the video. When the page plays the video again, the full-screen player opens again.
  • Do not tell customers to tap ×After the customer closes the player, iOS can keep the video paused. Then the guide frame shows a still picture, and the photo can show an old picture. Fix the app setting.
06 · Also check

Other camera settings in the same area

These items do not cause the full-screen player. Examine them while you change the web view.

  • Camera usage textThe app's Info.plist must have NSCameraUsageDescription. Without it, WebKit refuses camera access and the camera does not start.
  • A second permission promptFrom iOS 15, a WKWebView can ask for camera permission again for each site. To prevent this, implement webView(_:requestMediaCapturePermissionFor:initiatedByFrame:type:decisionHandler:) in your WKUIDelegate. Grant only for your own trusted host. In React Native, use mediaCapturePermissionGrantType="grantIfSameHostElsePrompt".
  • HTTPS onlyThe camera is available only on an HTTPS page. On an HTTP page, navigator.mediaDevices is undefined.

Source: the stream-capture repository. The preview element is in stream-capture/stream-capture.tsx.
