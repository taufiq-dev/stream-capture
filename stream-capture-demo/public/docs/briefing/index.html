Briefing for product and operations

Stream Capture

Stream Capture is the camera screen that takes the photo of a customer's ID card. It makes sure that the photo is sharp and large enough for the automatic ID check.

It opens the correct lensPhones have many rear lenses. Stream Capture finds the main lens, not the zoom lens.
It keeps all the pixelsThe photo has approximately 20 times more pixels than a simple camera page gives.
It reports each stepEach session gives timings, problems and one clear outcome for your dashboards.
01 · The customer's journey

Five steps, from the open screen to the sent photo

02 · Problem 1

Phones can open the wrong lens

Most new phones have two to four rear lenses. A simple camera page asks the browser for "a rear camera". The browser can then start the zoom lens. The card is too close, and the photo is not sharp.

03 · How the lens is selected

Each lens gets a score

Stream Capture reads what each lens reports: its resolution, its zoom range and its name. It adds points for resolution and for a main-lens name. It subtracts points for names like "tele", "wide" or "macro". A rear lens with the highest score starts.

04 · Problem 2

A simple page throws away most of the pixels

A simple camera page copies what the screen shows. A screen is small, so the photo of the card is small. Stream Capture cuts the same area from the full camera image instead.

05 · What the photo contains

The customer sees the card, the ID check gets a border too

The photo contains a small border around the frame. The ID check uses this border to find the card edges and to straighten the card. The customer sees only the frame area.

06 · Where the data goes

Stream Capture sends nothing to a server

Stream Capture gives the photo and the events to your own app on the phone. Your app's code decides where to send them. The only thing kept on the phone is the selected lens.

07 · What you can measure

Each session ends in exactly one outcome

Stream Capture reports each step to your analytics. Each session ends with one of three outcomes, never two. As a result, your funnel numbers always add up.

Time to previewFrom the open screen to the live camera.
Time to photoFrom the tap to the finished file.
Why the camera did not startPermission refused, camera in use by another app, or other.
Which lens each phone usedThis data shows phone models that select incorrectly.
Photo size and qualityPixels, file size and compression level of each photo.
OutcomePhoto taken, cancelled, or abandoned.
08 · Limits

What to know before launch

  • Real phones are necessary for testsA computer cannot test the lens selection. The project has no automatic tests. Only the code types are checked.
  • iPhones repeat the selectionSafari changes the camera IDs at each visit. Stream Capture then opens each lens for a short time again.
  • Older phones give smaller photosA phone with a 1080p camera preview gives a card photo of approximately 1000 px. This is still the exact frame area.
  • New phones can confuse the scoreThe score uses rules about lens names and zoom. The lens data in the events shows these phones. Developers can then add an override.
  • The demo keeps no photosThe public test page keeps the photo in the page memory only. The photo goes away when you close the tab.
